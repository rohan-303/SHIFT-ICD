# Project terminology

| Term | Working meaning |
|---|---|
| Source concept | A code and structured concept representation in the source release. |
| Target concept | A candidate code and structured concept representation in the target release. |
| Mapping | An evidence-bearing relationship between source and target concepts; not necessarily equivalence. |
| One-to-one | One source has one supported target alternative in the reference mapping. |
| One-to-many | One source has multiple supported target alternatives. |
| No-map | No plausible target translation is supplied by the authoritative mapping resource. |
| Approximate mapping | A relationship that is useful for comparison but does not represent exact equivalence. |
| Information loss | A transition in which source detail cannot be fully represented in the target. |
| Ontology shift | Change in concept definitions, hierarchy, granularity, availability, or relationships between releases. |
| Drift | Observable change in terminology or data distribution across versions or time. |
| Prediction set | A set of target candidates returned to represent uncertainty. |
| Selective prediction | A policy that may predict, defer for review, or abstain. |
| False acceptance | An incorrect mapping that the router nevertheless automatically accepts. |
| Postcoordination | Representing a concept using a stem plus one or more applicable extension codes. |

These definitions are provisional and must be refined against authoritative documentation during data inspection.
